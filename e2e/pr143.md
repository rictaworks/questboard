# PR #143: GoogleログインをXログイン（OAuth 2.0 + PKCE）に置き換え

- PR: https://github.com/rictaworks/questboard/pull/143
- 対応issue: https://github.com/rictaworks/questboard/issues/131

## 非エンジニア向けユーザーテスト手順

このPRはログイン方式そのものを変更するため、実際にブラウザでログインボタンを押すテストと、コマンドでの自動テスト確認の2種類を行います。

### 事前に開発担当者から受け取っておくもの（必須）

以下が揃っていないと画面でのログイン確認はできません。開発担当者に依頼して事前に受け取ってください。

1. X Developer Portalで発行された **X OAuth クライアントID**（`X_OAUTH_CLIENT_ID` / `NEXT_PUBLIC_X_CLIENT_ID`）
2. 上記アプリに登録された **コールバックURL**（`X_OAUTH_REDIRECT_URI` / `NEXT_PUBLIC_X_REDIRECT_URI`。例: `http://localhost:3000/auth/x/callback`）
3. **reCAPTCHAのサイトキー**（`NEXT_PUBLIC_RECAPTCHA_SITE_KEY`）
4. テストに使ってよい **Xアカウント**（自分のXアカウントでも可）
5. これらを設定した `.env` ファイル（フロント用・バックエンド用それぞれ）

上記が用意できない場合は、下記「手順A（画面確認）」は省略し、「手順B（自動テストのみ確認）」だけを実施してください。

補足: このPRは現時点で **下書き（Draft）状態** です。マージ前に開発担当者がDraftを解除したことを確認してから本番相当の確認を行ってください。

### 手順A: 画面でXログインを確認する（環境変数を受け取れた場合のみ）

1. 開発担当者から受け取った `.env` の内容を、指示された場所（フロントの `.env.local`、バックエンドの `src/backend/.env`）にコピー&ペーストして保存する
2. 開発担当者の指示に従い、アプリを起動する（例: `npm run dev` と、別ターミナルで `cd src/backend && bundle exec rails s`）
3. ブラウザで `http://localhost:3000` を開く
4. ログイン画面に「Xでログイン」のようなボタンが表示されていることを確認する（「Googleでログイン」という表示が残っていないこと）
5. そのボタンをクリックする
6. X（旧Twitter）の認可画面に遷移することを確認する
7. 手順4で用意したXアカウントでログインし、「連携を許可」する
8. questboardの画面に自動的に戻り、ログイン済みの状態（自分の名前やアイコンなどが表示される状態）になっていればOK

**合格ライン**: 「Xでログイン」ボタンからXの認可画面に遷移し、許可後にquestboardへ戻ってログイン状態になっていれば合格です。Googleのログイン画面が表示された場合は不合格です。

### 手順B: 自動テストの実行結果で確認する（環境変数がなくても実施可能）

1. プロジェクトのルートフォルダ（`questboard`）でターミナルを開く
2. 以下をコピー&ペーストしてEnterキーを押す
   ```
   node --test test/x-auth.test.mjs
   ```
3. 実行結果の最後の方に、次のような表示が出ればOKです
   ```
   ℹ pass 変更前と同じかそれ以上の件数
   ℹ fail 0
   ```
   「fail 0（失敗ゼロ）」であれば合格です。0でない数字が出た場合は、実行結果の全文をコピーして開発担当者に共有してください。

4. バックエンド側の確認は、開発担当者にPostgreSQLの起動（`docker compose up -d postgres`）を依頼した上で、以下を実行してもらい、同様に失敗0件であることを確認してください
   ```
   cd src/backend && bundle exec rspec spec/requests/auth_spec.rb spec/services/auth/x_oauth_client_spec.rb
   ```
