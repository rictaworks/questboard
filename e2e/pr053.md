# PR #53: sync-serverにop(操作)のブロードキャスト、Redis中継、WebSocket接続数メトリクスを追加

- PR: https://github.com/rictaworks/questboard/pull/53

## 非エンジニア向けユーザーテスト手順

**このPRについての重要な注意点**：今回の変更は、サーバー側（Go/Railsの内部処理）の土台を整えるものです。ボード画面（フロントエンド）側にはまだ「WebSocketでリアルタイム同期を受け取る」ボタンや画面が実装されていないため、**通常のボード画面を開いて操作しても、この機能の効果を目で確認することはできません**。そのため、以下ではサーバーが正しく起動し、想定通りに応答するかどうかを、ターミナル（黒い画面にコマンドを打ち込む画面）で確認する手順をご案内します。

開発者に近くにいてもらい、一緒に確認することをおすすめします。

### 事前に準備してもらうもの

- 開発担当者に、開発用サーバー（sync-serverおよびRailsのバックエンド）が動いているパソコン・ターミナルを用意してもらってください。
- 特別なAPIキーやパスワードは不要です（今回確認する範囲では、外部サービスへのログインは発生しません）。

### 手順1：sync-serverが起動していることを確認する

1. 開発担当者に、ターミナルで以下のコマンドを実行してもらいます。

   ```
   cd src/sync-server
   SYNC_SERVER_ENV=development go run ./cmd/sync-server
   ```

2. 画面に赤字のエラーが出ずに、コマンドがそのまま動き続けていれば起動成功です。

### 手順2：サーバーが「正常」と答えるか確認する（合格ライン）

1. 別のターミナルを開いてもらい、以下のコマンドを実行します。

   ```
   curl http://localhost:8080/healthz
   ```

2. 画面に次のような文字列が表示されればOKです（値は多少前後しても問題ありません）。

   ```
   {"status":"ok"}
   ```

   **これが表示されれば合格です。** エラーや空の応答、あるいは `curl: (7) Failed to connect` のような接続エラーが出た場合は、開発担当者に確認してもらってください。

### 手順3：接続数の計測（メトリクス）が動いているか確認する

1. 続けて同じターミナルで以下のコマンドを実行します。

   ```
   curl http://localhost:8080/metrics
   ```

2. 出力の中に `websocket_connections` という文字列と、それに続く数字（例：`websocket_connections 0`）が表示されればOKです。

   **この行が表示されれば合格です。** まだ誰も接続していない状態なので、数字は `0` で問題ありません。

### 手順4：バックエンド（Rails）側の自動テストが全て成功するか確認する

1. 開発担当者に、以下のコマンドを実行してもらいます。

   ```
   cd src/backend
   bundle exec rspec spec/services/sync_op_relay_spec.rb spec/requests/object_ops_spec.rb spec/requests/objects_spec.rb
   ```

2. 実行結果の最後に、次のように「失敗（failures）が0件」であることを示す行が表示されればOKです。

   ```
   0 failures
   ```

   **「0 failures」と表示されれば合格です。** それ以外の数字（例：`3 failures`）が出た場合は、開発担当者に修正を依頼してください。

以上の4つの手順すべてで「合格」が確認できれば、このPRの変更（sync-serverのop配信の土台、Redisによるノード間中継、接続数メトリクス、Rails側の操作ログ連携）が正しく動作していると判断できます。
