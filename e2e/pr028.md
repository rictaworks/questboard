# PR #28: Gin製sync-serverの雛形を追加（ヘルスチェック・WebSocketボードルーティング）

- PR: https://github.com/rictaworks/questboard/pull/28

## 非エンジニア向けユーザーテスト手順

このPRはユーザーの目に見える画面はありませんが、パソコンで「サーバーが正しく起動し、正しく応答するか」を確認できます。以下の手順どおりに操作してください。

### 準備するもの
- パソコン（Windows / Mac）
- ターミナル（Macなら「ターミナル」アプリ、Windowsなら「コマンドプロンプト」または「PowerShell」）
- Google Chromeなどのブラウザ

### 手順1: サーバーを起動する

1. ターミナルを開きます。
2. このプロジェクトのフォルダに移動します（例: `cd questboard`）。
3. 以下のコマンドを入力してEnterキーを押します。

   ```
   go run ./src/sync-server/cmd/sync-server
   ```

4. 画面にエラーが表示されず、`GET /healthz` や `GET /ws` といった文字が表示されれば起動成功です。
   - もし赤い文字でエラーが出た場合は、そのままスクリーンショットを撮って開発担当者に共有してください。

このターミナルはサーバーが動いている間ずっと開いたままにしてください。

### 手順2: ヘルスチェックを確認する

1. 新しくもう1つターミナルを開きます（手順1のものは閉じないでください）。
2. 以下のコマンドを入力してEnterキーを押します。

   ```
   curl http://localhost:8080/healthz
   ```

3. 画面に次のように表示されればOKです。

   ```
   {"status":"ok"}
   ```

### 手順3: リアルタイム接続（WebSocket）を確認する

1. Google Chromeを開きます。
2. キーボードの`F12`キーを押して「開発者ツール」を開きます。
3. 上のタブから「Console（コンソール）」を選びます。
4. 以下のコードをそのままコピーして、コンソールに貼り付けてEnterキーを押します。

   ```js
   const ws = new WebSocket("ws://localhost:8080/ws?boardId=test-board");
   ws.onopen = () => console.log("★接続成功★");
   ws.onclose = (event) => console.log("★接続終了★ コード:", event.code);
   ```

5. コンソールに `★接続成功★` と表示されればOKです。

### 手順4: サーバーを安全に終了できるか確認する

1. 手順3でブラウザのコンソールを開いたまま、手順1で開いたターミナルに戻ります。
2. `Ctrl + C` キーを押してサーバーを停止します。
3. ブラウザのコンソールに戻り、`★接続終了★ コード: 1001` のような表示が出ていればOKです（急に接続が切れるのではなく、きちんと終了の合図が送られてきたことを意味します）。

### すべてがOKなら

- 手順2で `{"status":"ok"}` が表示された
- 手順3で `★接続成功★` が表示された
- 手順4で `★接続終了★` が表示された

この3つがすべて確認できれば、このPRの動作確認は完了です。問題があれば、どの手順で・どんな表示が出たかを開発担当者に伝えてください。
