# PR #60: KPI分析イベントのバッチ処理・オフラインバッファリング・Rails取り込み機能を追加(偽造・PII対策込み)

- PR: https://github.com/rictaworks/questboard/pull/60

## 非エンジニア向けユーザーテスト手順

この変更は「画面の見た目」がほぼ変わらない裏側の機能追加（利用状況の記録）です。以下の手順で「エラーなく動いていること」を確認できれば合格です。

### 事前に必要なもの
- 開発担当者から、開発環境（テスト用サイト）のURLと、テスト用のGoogleアカウントでログインできる状態を用意してもらってください。
- 開発担当者から、開発環境のRailsサーバーのログを見せてもらう、または一緒に画面共有してもらう必要があります（ターミナル操作は開発担当者が行います）。

### 手順

1. 開発担当者に用意してもらった開発環境のURLをブラウザで開きます。
2. 用意されたテスト用Googleアカウントでログインします。
3. ログイン後、ボード一覧画面が表示されることを確認します。
   - **合格ライン**：エラーメッセージが出ずに画面が表示されればOKです。
4. 「新しいボードを作成」ボタンをクリックし、新しいボードを1つ作成します。
   - **合格ライン**：ボードが作成され、キャンバス画面に移動できればOKです。
5. 作成したボードの中で、付箋（ステッキー）を1つ追加し、適当な文字を入力します。
   - **合格ライン**：付箋がエラーなく画面に表示されればOKです。
6. 付箋にコメントを1件追加します。
   - **合格ライン**：コメントがエラーなく表示されればOKです。
7. ここで開発担当者に、以下のいずれかを確認してもらいます（非エンジニアの方はこの結果を「見せてもらうだけ」で構いません）。
   - 開発担当者のターミナルで `cd src/backend && bin/rails runner "puts KpiEvent.order(created_at: :desc).limit(5).pluck(:event_def_id, :created_at)"` を実行してもらい、手順4〜6で行った操作に対応する記録（直近数分以内のタイムスタンプ）が表示されること。
   - **合格ライン**：直近の操作に対応するKPIイベントの記録が一覧に表示され、氏名・メールアドレスなどの個人情報らしき文字列が含まれていなければOKです。
8. 一時的にスマートフォンやパソコンをインターネットから切断（機内モードなど）した状態で付箋をもう1つ追加してみます。
   - **合格ライン**：オフラインでもエラー画面が出ずに操作を続けられればOKです（記録は後でネットが繋がったときにまとめて送信されます）。
9. 再びインターネットに接続し、数秒〜数十秒待ちます。
   - **合格ライン**：特にエラーが表示されず、通常通り操作を続けられればOKです。

上記すべてで「合格ライン」を満たしていれば、このPRの動作確認は完了です。
