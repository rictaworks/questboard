## 非エンジニア向けユーザーテスト手順

このPRは、製品版（Xログイン）に向けてデータベースの土台を作り替える変更です。画面（UI）の見た目や操作は一切変わりません。「コマンドを実行して正しい結果が表示されるか」だけを確認してください。難しい専門知識は不要です。以下をコピー＆ペーストしていただければ確認できます。

### 事前に準備してもらうもの

- 特別なアカウント・APIキーは不要です。
- お使いのパソコン（またはGitHub Codespaces）に Docker と Ruby の開発環境が事前にセットアップされていることが前提です。セットアップ済みの環境を開発担当者から用意してもらってください。

### 確認手順

1. ターミナル（黒い操作画面）を開き、このプロジェクトのフォルダに移動します。
2. 以下のコマンドを実行し、データベース（PostgreSQL）を起動します。
   ```
   docker compose up -d postgres
   ```
   - **合格ライン**：赤い文字のエラーが出なければOKです。
3. 続けて以下のコマンドを1行ずつ実行し、バックエンドのフォルダに移動します。
   ```
   cd src/backend
   ```
4. 以下のコマンドを実行して、今回追加された確認用の自動テストを実行します。
   ```
   bundle exec rspec spec/models/schema_and_seed_spec.rb --format documentation
   ```

### 確認すること（ここが合格ラインです）

実行結果の一番下のあたりに、次のような表示が出ればOKです。

```
Questboard database schema and seeds
  defines the required tables, columns, and constraints
  seeds the 77 master rows idempotently

2 examples, 0 failures
```

- 「2 examples, 0 failures」という部分が重要です。「0 failures（失敗ゼロ）」と表示されていれば正常に動いています。
- もし「failures」の数字が0でない場合は、その実行結果の全文をコピーして開発担当者に共有してください。

### このPRで「見えるもの」「見えないもの」

- 見えないもの：画面上の見た目の変化はありません（ユーザーの識別方法をXアカウント基準に切り替える、データベースの内部構造だけの変更のため）。
- 見えるもの：上記テストコマンドの実行結果（合格「0 failures」／不合格）のみです。

上記が問題なければ、このPRは正常に動作しています。途中で赤字のエラーメッセージが出た場合は、その画面のスクリーンショットまたはターミナルの表示内容をコピーして開発担当者に共有してください。
