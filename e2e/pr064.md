# PR #64: BASIC認証で保護されたKPI開発者ダッシュボード(SSR)を追加

- PR: https://github.com/rictaworks/questboard/pull/64

## 非エンジニア向けユーザーテスト手順

以下の手順は、プログラミングの知識がなくても実行できます。作業を始める前に、開発担当者から次のものを受け取ってください。

- 確認用サイトのURL(例: `https://<開発環境のドメイン>/admin`)
- BASIC認証のユーザー名・パスワード(ブラウザでアクセスした際に表示される認証ダイアログ用)
- 確認対象のアプリ本体(ボード画面)のURL・ログイン情報(演出強度設定の確認に使用)

### 手順1: KPI管理画面が表示されることを確認する

1. Webブラウザ(Chrome、Safariなど)を開きます。
2. アドレスバーに、開発担当者から受け取った管理画面のURL(`/admin` で終わるもの)を入力し、Enterキーを押します。
3. ユーザー名とパスワードの入力を求めるポップアップ(認証ダイアログ)が表示されます。開発担当者から受け取ったユーザー名・パスワードを入力し、「ログイン」または「OK」を押します。
4. **合格ライン**: 「KPI」に関するタイトルと、いくつかの四角い枠(タイル)が並んだ画面が表示されればOKです。タイルの中には「D1継続率」「D7継続率」「クエスト完了率」といった日本語のラベルと、パーセント表示の数値が入っています。
5. 画面内の文字がすべて日本語になっていることを確認してください。英語の文字列が混ざっている場合は不具合です。
6. 画面のどこかに「本デモは最小データセットでの検証結果」という注意書きが表示されていることを確認してください。

> **追記（2026-07-29）**: 手順6の文言は変更済みです。questboard はデモではなく、また集計側にデータセットの制約も無いため、この注意書きは事実と異なっていました。現在は「継続率は初回イベントから7日以上経過した利用者のみを母数に集計」と表示されます（`KpiDashboardReport::MATURITY_WINDOW_DAYS` の実挙動）。手順6を実行する場合はこちらの文言で確認してください。

### 手順2: 認証なしではアクセスできないことを確認する

1. 先ほどとは別のブラウザ(例: シークレットウィンドウ/プライベートウィンドウ)を開きます。
   - Chromeの場合: 右上のメニュー(点3つ)から「新しいシークレットウィンドウ」を選びます。
2. 同じ管理画面のURLを入力してアクセスします。
3. **合格ライン**: ユーザー名・パスワードの入力を求めるポップアップが表示され、正しい情報を入力するまで画面の中身が見られない状態になっていればOKです。ポップアップをキャンセルした場合、「401」というエラー、または「認証が必要です」といった趣旨のエラー画面が表示されればOKです。

### 手順3: 演出強度設定のドロップダウンを確認する

1. 開発担当者から受け取ったアプリ本体(ボード画面)のURLにアクセスし、通常どおりログインします。
2. 設定に関するメニュー(歯車アイコンなど、開発担当者に場所を確認してください)を開きます。
3. 「演出強度」という項目があり、選択肢(プルダウン/ドロップダウン)になっていることを確認します。
4. 選択肢を切り替えて(例: 「弱」→「強」)、エラー画面が出たり、画面が固まったりしないことを確認します。
5. **合格ライン**: 演出強度の選択肢を切り替えてもアプリがクラッシュせず、選んだ内容が画面に反映される(または保存される)ことが確認できればOKです。
6. 手順1のKPI管理画面に戻り、しばらくしてから再読み込み(ブラウザの更新ボタン)をすると、「演出強度設定の分布」のタイルの数値が変化していれば、記録が正しく反映されている証拠です(即時反映されない場合は開発担当者に確認してください)。
