# PR #147: 手動フォロー再判定（15分クールダウン）とmember以外のプラン向け利用不可画面を追加

- PR: https://github.com/rictaworks/questboard/pull/147
- 対応issue: https://github.com/rictaworks/questboard/issues/133

## 非エンジニア向けユーザーテスト手順

### 事前に開発担当者から受け取るもの

| 受け取るもの | 用途 |
| --- | --- |
| テスト用のサイト URL（プレビュー環境のアドレス） | ブラウザで開く先。開発モードだと自動ログインされて今回の画面が出ないため、**必ずテスト用URLを使う** |
| フォロー対象の X アカウント名（`@` から始まる名前） | 手順6でフォローする相手。テスト用サイトに設定済みであることも確認してもらう（設定が漏れているときの表示は手順10で確認する） |
| テスト用の X アカウント（ID とパスワード）。**フォロー対象をまだフォローしていないもの** | ログインに使う。自分の普段のアカウントで対象を既にフォローしていると、利用不可画面が出ないため使えません |
| テスト用ボードの共有 URL（`.../b/` で始まるアドレス） | 手順5で使う。招待される側の画面を確認するため、開発担当者に事前に1つ作っておいてもらう |
| （任意）クールダウン時間を 15 分から 1 分へ一時的に短縮してもらう依頼 | 待ち時間を短くしたい場合のみ。短縮した場合は、以下の「15分」を「1分」に読み替える |

### 手順1：利用不可画面が出ることを確認する

1. ブラウザ（Chrome など）で、受け取ったテスト用の URL を開く。
2. 画面上の **「Xで続ける」** ボタンをクリックする。
3. X のログイン画面が出るので、**フォローしていないテスト用アカウント**でログインし、「アプリにアクセスを許可」をクリックする。
4. 元の画面に戻ったら、次の3行の文章と2つのボタンが表示されていることを確認する（`@対象アカウント` の部分には、受け取ったフォロー対象のアカウント名が入る）。

   - 「このプランでは利用できません」
   - 「現在の判定では、ボード作成や参加は利用できません。」
   - 「ボードを使うには @対象アカウント をフォローしてください。フォロー後に手動再判定を実行すると利用できるようになります。」
   - 「@対象アカウント のプロフィールを開く」ボタン（枠線付きのボタン表示）
   - **「手動再判定」** ボタン

   - **合格ライン**：上の3行の文章と、2つのボタン（「プロフィールを開く」「手動再判定」）が表示され、ボードのタイトル入力欄が表示されていないこと。
   - **NG例**：ボード作成フォームが普通に表示される／画面が真っ白／英語のメッセージが出る／アカウント名の部分が空欄や `{handle}` のままになっている／「プロフィールを開く」が本文と同じ見た目でボタンだと分からない。

### 手順2：フォロー先の導線が正しいことを確認する

5. 「@対象アカウント のプロフィールを開く」ボタンをクリックする。
6. **新しいタブ**が開き、受け取ったフォロー対象アカウントの X プロフィールが表示されることを確認する。

   - **合格ライン**：新しいタブで、案内文に書かれているのと同じアカウントのプロフィールが開くこと。
   - **NG例**：同じタブで開いてテスト中の画面が消える／別人のアカウントが開く／エラーページになる。
7. 確認したら、**まだフォローせずに**元のタブへ戻る（フォローは手順6で行う）。

### 手順3：1回目の手動再判定を実行する

8. **「手動再判定」** ボタンをクリックする。
9. ボタンの表示が **「再判定中」**（くるくる回るアイコン付き）に変わり、数秒後に「手動再判定」へ戻ることを確認する。
10. まだフォローしていないので、画面は手順1と同じ利用不可のままになる。

    - **合格ライン**：ボタンが「再判定中」→「手動再判定」と切り替わり、画面がエラーで固まらないこと。

### 手順4：クールダウン中は残り時間を出して拒否されることを確認する（重要）

11. 手順3の直後（**15分以内**）に、もう一度 **「手動再判定」** ボタンをクリックする。
12. 画面に赤い文字で、**残り時間つきの日本語メッセージ**が表示されることを確認する。

    表示例：`手動再判定はあと14分52秒後にできます`

    - **合格ライン**：「手動再判定はあと◯分◯秒後にできます」という**日本語**のメッセージが出て、再判定が実行されないこと。
13. スマホの時計などで**1分待ってから**、もう一度「手動再判定」をクリックする。表示される残り時間が約1分減っていること（例：`あと14分52秒` → `あと13分52秒`）を確認する。

    - **合格ライン**：押すたびに残り時間が正しく減っていくこと。
    - **NG例**：残り時間が毎回同じ数字／`cooldown` などの英語が出る／メッセージが出ずに画面が変わってしまう。

### 手順5：共有 URL（招待リンク）でも同じ画面が出ることを確認する

14. 同じブラウザ（テスト用アカウントでログインしたまま）で、受け取った**テスト用ボードの共有 URL** を開く。
15. ボードの中身や参加フォームではなく、手順1と同じ利用不可画面（3行の文章＋「プロフィールを開く」「手動再判定」の2つのボタン）が表示されることを確認する。

    - **合格ライン**：共有 URL でもボード内容が見えず、利用不可画面とフォロー案内・「手動再判定」ボタンが出ること。
    - **NG例**：`403` や「権限がありません」といった素っ気ないエラーだけが出る／ボードの中身が見えてしまう／エラーメッセージと利用不可画面が二重に出る。
16. この画面の **「手動再判定」** ボタンもクリックできることを確認する（クールダウン中なら手順4と同じ残り時間メッセージが出る）。

    - **合格ライン**：共有 URL の画面からでも再判定ボタンが動作し、クールダウン中は同じ日本語メッセージが出ること。

### 手順6：フォローしてから再判定すると使えるようになることを確認する

17. 別のタブで X を開き、テスト用アカウントのまま、受け取ったフォロー対象アカウントを **フォロー** する。
18. テスト用サイトのタブに戻り、直前に「手動再判定」を押した時刻から **15分**（短縮してもらった場合は1分）経過するのを待つ。
19. トップページ（テスト用サイトの URL）を開き、**「手動再判定」** ボタンをクリックする。
20. 利用不可画面が消えて、**ボード作成のタイトル入力欄と作成ボタン**が表示されることを確認する。
21. タイトルに `テスト用ボード` と入力して作成ボタンをクリックし、共有 URL が表示されることを確認する。
22. 手順5で使った共有 URL をもう一度開き、今度は利用不可画面ではなく**ボードの参加画面／ボードの中身**が表示されることを確認する。

    - **合格ライン**：手順20で利用不可画面がボード作成フォームに切り替わり、手順21でボードが作成でき、手順22で共有 URL からボードに入れること。
    - **NG例**：フォロー済みなのに利用不可画面のままになる（この場合、押した時刻とスクリーンショットを添えて報告してください）。

### 手順7：フォローを外しても即座には利用不可にならない（仕様どおりの動作の確認）

> ここは「バグではない」ことを確認する手順です。**不具合として報告しないでください。**

23. 手順6のあと、X でフォロー対象アカウントの **フォローを外す**。
24. 15分待ってからテスト用サイトで操作しても、**すぐには利用不可画面に戻らない**（引き続きボードを使える）ことを確認する。

    - **合格ライン**：フォローを外しても、その場では利用不可にならないこと。
    - 理由：手動再判定は「フォローされたことを見つけて使えるようにする」専用の仕組みで、「フォローを外したこと」の判定は毎日動くサーバー側の定期処理が行います。手順24で即座に利用不可になった場合のみ、想定外の動作として報告してください。

### 手順8（画面を使わない確認・任意）

画面が使えない場合や、サーバー側の応答だけを確認したい場合に実施します。**開発担当者からバックエンドの URL とテスト用のログイン済み Cookie（`Cookie: ...` の1行）を受け取ってください。**

以下をターミナルにコピー&ペーストし、`<バックエンドURL>` と `<受け取ったCookie>` を置き換えて、**続けて2回**実行します。

```bash
curl -i -X POST "<バックエンドURL>/session/recheck" \
  -H "Content-Type: application/json" \
  -H "Cookie: <受け取ったCookie>"
```

- **合格ライン**
- 1回目：先頭行が `HTTP/1.1 200 OK`（または `HTTP/2 200`）で、`planCode` を含む結果が返る。
- 2回目（1回目の直後）：先頭行が `HTTP/1.1 429`（または `HTTP/2 429`）で、`手動再判定はあと◯分◯秒後にできます` という日本語メッセージが返る。

同じコマンドから、`Cookie` の行を**丸ごと消して**もう一度実行します。

- **合格ライン**：先頭行が `HTTP/1.1 401`（または `HTTP/2 401`）になり、ログインしていない状態では再判定できないこと。

### 手順9（X 側が落ちているときの表示・任意／開発担当者と一緒に実施）

X の API に一時的につながらない状態を開発担当者に作ってもらい（X 用のトークンを一時的に無効な値にしてもらう等）、クールダウンが明けた状態で **「手動再判定」** ボタンをクリックします。

- **合格ライン**
- 画面に `フォロー状態を確認できませんでした。時間をおいて再度お試しください` という**日本語**のメッセージが赤字で出ること。
- 画面が真っ白になったり、`500` や英語のエラー文字列がそのまま出たりしないこと。
- この失敗のあとにボードが使えるようになったり、逆に使えていたものが使えなくなったりしないこと（判定は変わらないのが正しい動作）。
- なお、この失敗でもクールダウンは始まります（次に押せるのは15分後）。仕様どおりなので不具合ではありません。

### 手順10（フォロー対象アカウントの設定が漏れているときの表示・任意／開発担当者と一緒に実施）

今回の修正で表示が変わった箇所です。設定が漏れていても、ログイン済みの人に「ログインし直し」を求めないこと、また画面には英語の内部エラーではなく日本語の案内文だけが出ることを確認します。

開発担当者に、テスト用サイトの「フォロー対象アカウント名の設定（`NEXT_PUBLIC_X_FOLLOW_TARGET_HANDLE`）」を一時的に空にして、サイトを再公開してもらってください。**確認が終わったら必ず元に戻してもらうこと。**

25. フォロー対象を**フォローしていない**テスト用アカウントでログインした状態のまま、テスト用サイトのトップページを開く。
26. 表示された画面を確認する。

    - **合格ライン**
      - 「このプランでは利用できません」「現在の判定では、ボード作成や参加は利用できません。」が表示されること。
      - **「手動再判定」** ボタンが表示されていること。
      - 赤い文字で、**日本語**の「フォロー対象のハンドルが設定されていません。」というメッセージだけが表示されること。英語のエラー文字列（`NEXT_PUBLIC_X_FOLLOW_TARGET_HANDLE is required` など）は画面には出ません。もし画面に出ている場合は不具合として報告してください（ブラウザの開発者ツールを開ける方は、コンソールに同種の英語メッセージが出ていることも合わせて確認できますが、これは開発者向けの記録であり必須の確認ではありません）。
      - フォロー案内の文章（「… をフォローしてください」）と「プロフィールを開く」ボタンは**出ません**。案内先のアカウント名が分からないためで、これも想定どおりです。
    - **NG例（修正前に出ていた症状です。出たら報告してください）**
      - 画面に英語のエラー文字列（`NEXT_PUBLIC_X_FOLLOW_TARGET_HANDLE is required` など）がそのまま表示される。
      - ログイン済みなのに「Xでログイン」ボタンのある**ログインを促す画面**が出る。
      - ボード作成のタイトル入力欄が表示され、そのまま使えてしまう。
      - 画面が真っ白になる。
27. 開発担当者に設定を元へ戻してもらい、トップページを開き直して、手順1の画面（フォロー案内とプロフィールへのボタンがある状態）に戻ることを確認する。

    - **合格ライン**：設定を戻すと、赤い文字のエラー表示が消え、フォロー案内が表示されること。

### 不具合が見つかったときの報告内容

- 実施した手順の番号
- 画面のスクリーンショット（赤いメッセージが出ている場合はそれも含める）
- 操作した日時（例：2026-08-13 15:20 頃）
- 使用したテスト用 X アカウント名
