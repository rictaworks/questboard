# PR #172: tombstone復元権限をdelete権限から分離する

- PR: https://github.com/rictaworks/questboard/pull/172
- 対応issue: https://github.com/rictaworks/questboard/issues/58

## 非エンジニア向けユーザーテスト手順

この変更は「付箋（ボード上のオブジェクト）を削除したり元に戻したりする際に、誰にその操作を許可するか」を裏側で正しく判定し直すものです。以下の2部構成で確認してください。

### 事前に必要なもの

- このリポジトリをパソコンにダウンロード（clone）済みであること
- Docker Desktop がインストールされ、起動していること
- Node.js がインストールされていること
- 開発担当者から特別な認証情報を受け取る必要はありません

### パート1：自動テストで正しく判定できることを確認する（確実な方法）

削除・復元の権限判定は、複数人が同時に同じボードを編集しているときにだけ発生する一瞬のタイミングで動くため、画面操作だけで確実に再現するのが難しい変更です。そのため、まず自動テストの実行結果で確認します。

1. パソコンで「ターミナル」（Macなら「ターミナル」、Windowsなら「コマンドプロンプト」や「WSL」）を開きます。
2. 以下のコマンドを1行ずつ入力し、Enterキーを押します。

   ```
   cd questboard
   docker compose up -d postgres
   ```

3. 10秒ほど待ってから、以下のコマンドを入力してEnterキーを押します。

   ```
   cd src/backend
   bundle exec rspec spec/requests/object_ops_spec.rb spec/services/permission_service_spec.rb
   ```

4. 実行が終わったら、続けて以下のコマンドを入力してEnterキーを押します（ターミナルの場所をリポジトリの一番上に戻してから実行してください）。

   ```
   cd ../..
   node --test test/board-permissions.test.mjs
   ```

**合格ライン（パート1）**

- 手順3の結果の最後の方に、赤い文字の「failures」が **0件** と表示されていればOKです（例：`0 examples, 0 failures`）。
- 手順4の結果に赤い文字の「fail」が **0件**、「pass」の数が1以上表示されていればOKです。
- もし失敗（failures / fail）の数が0でない場合は、その画面をスクリーンショットで撮って開発担当者に共有してください。

### パート2：画面上での基本動作の確認（回帰チェック）

1. ボードの管理者（オーナー）権限を持つアカウントでログインし、任意のボードを開きます。
2. 画面上に付箋（四角い図形）を1つ新規作成します。
3. 作成した付箋をクリックして選択し、Deleteキー（削除キー）を押すか、削除ボタンを押します。
   - **合格ライン**：付箋が画面から消えればOKです。
4. 続けて、閲覧のみ（ビューアー）権限を付与された別アカウントで同じボードを開き、付箋を1つ選択してDeleteキーを押してみます。
   - **合格ライン**：付箋が消えず、「このオブジェクトは編集できません。」というメッセージが表示されればOKです（削除できてしまった場合は問題です）。

以上のパート1・パート2がいずれも合格ラインを満たしていれば、この変更は正しく動作しています。
