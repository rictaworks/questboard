# PR #61: オンボーディングクエストをKPIイベント（F8）から進行させる

- PR: https://github.com/rictaworks/questboard/pull/61

## ユーザーテスト手順（非エンジニア向け）

### 準備

1. ターミナルを3つ開き、それぞれで以下を実行します（すべて起動したままにしてください）

   ```bash
   # 1つ目：フロントエンド
   npm run dev

   # 2つ目：バックエンド
   cd src/backend && bin/rails server

   # 3つ目：同期サーバー
   cd src/sync-server && go run .
   ```

2. ブラウザで `http://localhost:3000/ja` を開きます
   - 開発環境ではログイン済みとして扱われるため、**Googleログインは不要**です

3. ボードを作成し、ボード画面（`/ja/b/（共有トークン）`）を開きます

### テスト1：クエストが操作に応じて進むこと

1. 画面上の「オンボーディングクエスト」パネルを確認します
2. 「付箋を3枚作る」が **0/3** と表示されていることを確認します
3. 付箋を1枚作ります → 表示が **1/3** に変わることを確認します
4. さらに2枚作ります → **3/3** になり、**お祝いの表示が出る**ことを確認します
5. 他のクエスト（ズームする、ラジアルメニューを開く など）も同様に、その操作をすると進むことを確認します

### テスト2：ページを開き直しても進捗が残ること ⭐今回の修正点

1. テスト1のあと、**ブラウザを再読み込み**します
2. 完了したクエストが**完了したまま**表示されることを確認します
3. このとき、**お祝いの表示が再び出ないこと**を確認します
   - 以前は開き直すたびにお祝いが出てしまっていました

### テスト3：スキップと再開

1. 未完了のクエストの「スキップ」を押します → 表示が「スキップ」に変わることを確認します
2. スキップしたクエストの条件にあたる操作をします → **進捗が進まない**ことを確認します
3. 「再開」を押します → 「進行中」に戻ることを確認します
4. もう一度同じ操作をします → 今度は**進捗が進む**ことを確認します

### テスト4：通信が切れても表示が正しく戻ること

1. ブラウザの開発者ツール（F12）を開き、「ネットワーク」タブで **オフライン** に切り替えます
2. その状態で付箋を作るなどの操作をします
3. **オンライン** に戻します
4. しばらく待つと、オフライン中の操作分も含めて**進捗が正しい数字に追いつく**ことを確認します

### テスト5：他の人のクエストが見えないこと（セキュリティ）

1. ブラウザを2つ（通常ウィンドウとシークレットウィンドウ）用意し、**別々の利用者として**同じボードを開きます
2. 片方でクエストを進めます
3. もう片方の画面で、**相手のクエスト進捗が表示されないこと**を確認します
   - 各自のクエストパネルには、自分の進捗だけが表示されるのが正しい状態です

### すべてのクエストを終えたとき

- 8つすべてが「完了」または「スキップ」になると、**クエストパネル自体が自動的に消える**ことを確認します
