# PR #55: テキスト共同編集(CRDT)の中継とpresenceのスロットリングを追加

- PR: https://github.com/rictaworks/questboard/pull/55

## 非エンジニア向けユーザーテスト手順

**このPRについての重要な注意点**：今回の変更は、サーバー側（RailsとGo/sync-serverの内部処理）のロジックを整えるものです。ボード画面（フロントエンド）側にはまだ、複数人でのテキスト共同編集やカーソル表示を操作できる画面が実装されていないため、**通常のボード画面を操作しても、この機能の効果を目で確認することはできません**。そのため、以下ではサーバーの自動テストを実行し、結果を確認する手順をご案内します。

開発担当者に近くにいてもらい、一緒に確認することをおすすめします。

### 事前に準備してもらうもの

- 開発担当者に、開発用のパソコン・ターミナル（黒い画面にコマンドを打ち込む画面）を用意してもらってください。
- 特別なAPIキーやパスワードは不要です（今回確認する範囲では、外部サービスへのログインは発生しません）。

### 手順1：テキスト共同編集（OT）と重複送信対策が正しく動くか確認する（Railsバックエンド側）

1. 開発担当者に、ターミナルで以下のコマンドを実行してもらいます。

   ```
   cd src/backend
   bundle exec rspec spec/requests/object_ops_spec.rb spec/requests/boards_spec.rb spec/migrations/backfill_text_crdt_revision_spec.rb
   ```

2. 実行結果の一番下に、次のように「失敗（failures）が0件」であることを示す行が表示されればOKです。

   ```
   0 failures
   ```

   **「0 failures」と表示されれば合格です。** それ以外の数字（例：`2 failures`）が出た場合は、開発担当者に修正を依頼してください。

### 手順2：presence（カーソル表示）のスロットリングとDoS対策が正しく動くか確認する（sync-server側）

1. 続けて、以下のコマンドを実行してもらいます。

   ```
   cd src/sync-server
   go test ./internal/ws/... ./internal/server/...
   ```

2. 実行結果の最後に、次のように `ok` という文字と `FAIL` の文字が含まれていない行が表示されればOKです。

   ```
   ok  	github.com/rictaworks/questboard/src/sync-server/internal/ws	(cached)
   ok  	github.com/rictaworks/questboard/src/sync-server/internal/server	(cached)
   ```

   **`ok` と表示され、`FAIL` という文字がどこにも出ていなければ合格です。** `FAIL` の文字が含まれる場合は、開発担当者に修正を依頼してください。

以上の2つの手順すべてで「合格」が確認できれば、このPRの変更（テキスト共同編集の正確な収束、書式の保持、絵文字を含む文章の文字化け防止、重複送信対策、DoS対策、presenceのスロットリング）が正しく動作していると判断できます。
