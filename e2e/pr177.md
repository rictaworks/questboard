# PR #177: ユーザー削除時の外部キー挙動を明文化してFK制約を整理

- PR: https://github.com/rictaworks/questboard/pull/177
- 対応issue: https://github.com/rictaworks/questboard/issues/31

## 非エンジニア向けユーザーテスト手順

**このPRはデータベースの内部設計（ユーザー削除時に関連データをどう扱うか）を変更するものです。画面の見た目や操作方法は一切変わりません。** 現時点では管理画面にも「ユーザーを削除するボタン」自体が存在しないため、画面上で確認できる操作はありません。代わりに、以下の手順でコマンドを実行し、変更が正しく反映されていることを確認してください。

### 事前に必要なもの

- 開発担当者から受け取るもの：この作業用のパソコンに `questboard` のソースコードが用意されていること（開発担当者にセットアップしてもらってください）
- Docker Desktop がインストール・起動していること
- 特別なパスワードやAPIキーは不要です

### 手順

1. パソコンで「ターミナル」（Macの場合はターミナル.app、Windowsの場合はGit BashやWSL）を開きます。
2. 以下のコマンドを1行ずつコピーして貼り付け、Enterキーを押します。データベースを起動するコマンドです。
   ```
   docker compose up -d postgres
   ```
3. 続けて、バックエンドのフォルダに移動します。
   ```
   cd src/backend
   ```
4. 今回の変更を確認するテストを実行します。
   ```
   bundle exec rspec spec/models/user_spec.rb spec/models/schema_and_seed_spec.rb
   ```
5. 実行後、画面の一番下あたりに次のような行が表示されればOKです（数字はテストの件数なので多少前後しても構いません）。
   ```
   0 failures
   ```
   もし `failures` の数字が0より大きい場合や、赤色の文字で `Failure` が表示された場合はNGです。その場合は開発担当者に画面のスクリーンショットを送ってください。

### 合格ライン

- 手順4のコマンド実行後、`0 failures` と表示されること（画面が赤色のエラーで埋まっていないこと）
- コマンド実行中にエラーで止まらず、最後まで完了すること
