# PR #165: board_membersにuser_idインデックスを追加してユーザー別ボード検索を高速化

- PR: https://github.com/rictaworks/questboard/pull/165
- 対応issue: https://github.com/rictaworks/questboard/issues/34

## 非エンジニア向けユーザーテスト手順

この変更は画面に表示される機能ではなく、データベースの検索速度を改善する裏側の変更です。以下の手順で「正しく反映されているか」をコマンドの実行結果で確認します。

### 事前に必要なもの

- このリポジトリを開発環境で動かせる状態（Docker Composeが使えること）
- 開発担当者から追加で受け取る必要のある認証情報・APIキーは **ありません**

### 手順

1. ターミナル（コマンドを打つ黒い画面）を開き、リポジトリのルートフォルダに移動します。

2. データベースを起動します。

   ```
   docker compose up -d postgres
   ```

3. Railsのテスト用データベースにこの変更（マイグレーション）を反映します。

   ```
   cd src/backend
   bundle exec rails db:migrate
   ```

   - **合格ライン**：エラーが表示されず、`AddUserIdIndexToBoardMembers: migrated` のような行が表示されればOKです。

4. 自動テストを実行して、インデックスが正しく作られて実際に使われているかを確認します。

   ```
   bundle exec rspec spec/models/schema_and_seed_spec.rb
   ```

   - **合格ライン**：最後に赤い文字（失敗）が出ず、`0 failures` と表示されればOKです。緑色の `.`（ピリオド）が並んでいれば正常に進んでいる合図です。

5. （任意・より詳しく確認したい場合）データベースに直接インデックスの一覧を確認します。

   ```
   docker compose exec postgres psql -U postgres -d questboard_test -c "\d board_members"
   ```

   - **合格ライン**：出力の中に `index_board_members_on_user_id` という名前の行が表示されればOKです。

以上がすべて表示されれば、この変更は正しく反映されています。
