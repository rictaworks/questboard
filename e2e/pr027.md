# PR #27: Rails APIの雛形を追加（環境別DB切り替え・ヘルスチェック・管理画面BASIC認証・CORS）

- PR: https://github.com/rictaworks/questboard/pull/27

## 非エンジニア向け動作確認手順

このPRは画面のないバックエンドAPIなので、コマンドとブラウザの両方を使って確認します。以下の手順通りに進めてください。

### 事前準備

1. ターミナルを開き、次のフォルダに移動します。
   ```
   cd src/backend
   ```
2. 設定ファイルをコピーします。
   ```
   cp .env.example .env
   ```
3. 必要なプログラムをインストールします。
   ```
   bundle install
   ```
4. サーバーを起動します。
   ```
   bundle exec rails server
   ```
   「Listening on ...」という表示が出れば起動成功です。

### 確認①：サーバーが生きているか（ヘルスチェック）

- 別のターミナルを開き、次のコマンドを実行します。
  ```
  curl http://localhost:3000/healthz
  ```
- `{"status":"ok"}` という文字列が返ってくれば成功です。

### 確認②：管理画面が認証なしでは見られないこと

- ブラウザで `http://localhost:3000/admin` を開いてください。
- ユーザー名とパスワードを求めるポップアップ（認証ダイアログ）が表示されることを確認してください。**何も聞かれずに画面が表示された場合はNGです。**

### 確認③：正しいID・パスワードで管理画面が見られること

- `.env` ファイルに記載した `ADMIN_BASIC_AUTH_USERNAME` と `ADMIN_BASIC_AUTH_PASSWORD` の値を、確認②のポップアップに入力してください。
- `{"status":"ok","area":"admin"}` という文字列が表示されれば成功です。

### 確認④：ID・パスワード未設定時に安全に拒否されること

- サーバーを一度 `Ctrl+C` で停止します。
- `.env` ファイルの `ADMIN_BASIC_AUTH_USERNAME=` と `ADMIN_BASIC_AUTH_PASSWORD=` の行を空欄にして保存します。
- サーバーを再起動し、再度 `http://localhost:3000/admin` にアクセスしてください。
- エラーで落ちたり素通りで画面が見えてしまったりせず、**認証を求めるポップアップが表示される**ことを確認してください（設定を忘れても安全側に倒れる、という今回の修正ポイントです）。
- 確認後は `.env` のID・パスワードを元の値に戻しておいてください。

### 確認⑤：自動テストがすべて成功すること

- ターミナルで次のコマンドを実行します。
  ```
  bundle exec rspec
  ```
- 最後に `3 examples, 0 failures` のように表示されれば成功です（`failures`が0件であることが重要です）。

すべての項目で問題がなければ、動作確認は完了です。おかしな点があれば、該当する確認番号（例：確認②）と表示された内容のスクリーンショットを添えてご連絡ください。
