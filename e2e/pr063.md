# PR #63: 開発・テスト環境のDBをSQLiteからPostgreSQLへ移行

- PR: https://github.com/rictaworks/questboard/pull/63

## 非エンジニア向けユーザーテスト手順

このPRは、開発・テスト環境のデータベースをSQLiteからPostgreSQLに切り替えるものです。画面の見た目や操作方法は変わりません。以下の手順で「今まで通りアプリが問題なく動くこと」を確認してください。

### 事前に準備してもらうもの

- 特別なアカウント・APIキーは不要です。
- お使いのパソコンに Docker（Docker Desktop など）と Node.js、Ruby の開発環境が事前にセットアップされていることが前提です。開発担当者にセットアップ済みのパソコンを用意してもらってください。

### 確認手順

1. ターミナル（黒い画面のアプリ）を開き、このプロジェクトのフォルダに移動します。
2. 以下のコマンドを1行ずつ実行し、データベース（PostgreSQL）を起動します。
   ```
   docker compose up -d postgres
   ```
   実行後、エラーが赤い文字で表示されなければOKです。
3. 次のコマンドを実行して、設定ファイルを準備します。
   ```
   cp src/backend/.env.example src/backend/.env
   ```
4. 次のコマンドを実行して、データベースの中身（テーブルなど）を用意します。
   ```
   cd src/backend && bundle exec rails db:prepare
   ```
   - **合格ライン**：`Created database` や特にエラーメッセージが出ずにコマンドが終了すればOKです。赤字で `Error` と表示された場合はNGです。
5. プロジェクトのルートフォルダに戻り、普段通りの起動コマンド（例：`npm run dev` など、開発担当者から案内されている起動方法）でアプリを起動します。
6. ブラウザで普段アクセスしているURL（例：`http://localhost:3000`）を開きます。
   - **合格ライン**：いつも通りログイン画面またはトップ画面が表示されればOKです。真っ白な画面やエラー画面が出た場合はNGです。
7. 実際にログインし、いつも使っている画面（ボード一覧・ボード作成・クエスト画面など）をいくつかクリックして開いてみます。
   - **合格ライン**：これまでと同じようにデータが表示され、ボタン操作やページ移動でエラー表示が出なければOKです。
8. 何か新しいデータ（ボードの作成やクエストの進行など）を1つ試しに登録・更新してみます。
   - **合格ライン**：保存後、画面が正常に更新され、内容が消えずに反映されていればOKです。

上記すべてが問題なければ、このPRは正常に動作しています。途中でエラー画面や赤字のエラーメッセージが出た場合は、その画面のスクリーンショットを開発担当者に共有してください。
