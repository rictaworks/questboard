# PR #66: 死活監視・同期メトリクス・保守運用runbookの追加(issue #23対応)

- PR: https://github.com/rictaworks/questboard/pull/66

## 非エンジニア向けユーザーテスト手順

このPRはバックエンド・インフラ寄りの変更が中心で、ブラウザ上で見た目が変わる画面はありません。そのため、以下の手順は「開発担当者による技術確認」が中心になります。専門知識のない方が実施する場合は、開発担当者に立ち会ってもらいながら進めてください。

**事前に開発担当者から受け取っておくもの**
- 確認対象の環境のURL(例: 開発サーバーのアドレス)
- ターミナル(コマンドを実行する黒い画面)を開く手順、または開発担当者の画面共有

1. **死活監視(ヘルスチェック)が正常に動くことの確認**
   1. ターミナルで以下のコマンドを実行します(`<backend-url>` は開発担当者から教えてもらったバックエンドのアドレスに置き換えてください)。
      ```
      curl -i <backend-url>/healthz
      ```
   2. 合格ライン: 画面に `HTTP/1.1 200 OK` のような表示が出ればOKです。数字の `200` が出ていることを確認してください。
   3. 開発担当者にデータベースを一時的に止めてもらい、同じコマンドをもう一度実行してもらいます。
   4. 合格ライン: 今度は `503` という数字が表示されればOKです(「異常があるときはちゃんと異常と教えてくれる」ことの確認です)。

2. **監視用の数値(メトリクス)が取得できることの確認**
   1. ターミナルで以下のコマンドを実行します(`<sync-server-url>` はsync-serverのアドレスに置き換えてください)。
      ```
      curl <sync-server-url>/metrics
      ```
   2. 合格ライン: 画面にたくさんの英数字の行が表示され、その中に `sync_server_sync_operation_duration_seconds` という文字列が含まれていればOKです。

3. **エラー報告の受付が動くことの確認**
   1. 開発担当者にブラウザの開発者ツールを開いてもらい、フロントエンド画面でわざとエラーを起こしてもらいます。
   2. 合格ライン: 開発担当者側でRailsのログに、そのエラーの内容が記録されていることを確認してもらえればOKです(この確認は開発担当者に依頼してください)。

上記1〜3は、いずれも「見た目の確認」ではなく「コマンドの実行結果を確認する」作業です。実行が難しい場合は、開発担当者にこの手順どおりに実施してもらい、結果のスクリーンショットを共有してもらう形でも構いません。
