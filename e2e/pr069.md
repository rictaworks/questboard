# PR #69: SentryによるエラートラッキングをRails/Next.jsに導入

- PR: https://github.com/rictaworks/questboard/pull/69

## 非エンジニア向けユーザーテスト手順

このPRはSentry（本番環境限定の外部エラー監視サービス）を導入するものですが、**本番環境でDSN（Sentryへの接続キー）が設定されている場合のみ動作する機能**です。開発環境では今まで通りの動作になるため、ここでは「アプリが問題なく起動し、既存のエラー通知の仕組みが変わらず動くこと」を確認します。

### 事前に必要なもの

- 開発担当者（Antigravity/Claude担当者）から、このブランチを動かせる開発環境（PC・ターミナル）を用意してもらってください
- 特別なパスワードやAPIキーは不要です（本番用のSentry DSNは今回のテストでは使いません）

### 手順

1. ターミナル（黒い画面のアプリ）を開き、リポジトリのフォルダに移動する
2. 次のコマンドを1行ずつ実行し、フロントエンドの開発サーバーを起動する
   ```
   npm install
   npm run dev
   ```
3. ターミナルに `Local: http://localhost:3000` のような表示が出たら、ブラウザでそのURLを開く
4. トップページ（言語選択後のログイン画面）が今まで通り表示されればOKです。真っ白な画面やエラー画面が出ていないことを確認してください
5. 別のターミナルを開き、バックエンド（Rails）のフォルダで次のコマンドを実行する
   ```
   cd src/backend
   bundle exec rails server
   ```
6. エラーで止まらずに `Listening on` のような表示が出て起動が続けばOKです
7. ブラウザの開発者ツール（右クリック→「検証」または「Inspect」→「Console」タブ）を開いた状態で、手順3のページをいくつかクリックして操作してみる
8. 画面が固まったり、赤い大きなエラーメッセージがコンソールに大量に出続けたりしなければOKです（通常のログ出力は問題ありません）

### 合格ライン

- 上記のいずれの手順でも、アプリがクラッシュせず、これまでと同じようにページが表示され、操作できること
- ターミナルにSentryの接続キー（DSN）に関するエラーメッセージ（例：「DSNが不正です」等）が出ていないこと

開発環境ではSentryへの接続自体が行われない設計のため、「Sentryにエラーが届くかどうか」の確認は今回のテスト範囲外です（本番運用開始後、開発担当者が別途確認します）。
