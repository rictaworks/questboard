# PR #146: プラン値ベースの機能ゲートを追加し、フォロー判定依存を排除

- PR: https://github.com/rictaworks/questboard/pull/146
- 対応issue: https://github.com/rictaworks/questboard/issues/135

## 非エンジニア向けユーザーテスト手順

この変更は画面を持たない、サーバー内部の権限チェックの変更です。画面での確認はできないため、ターミナル（黒い画面のコマンド入力ツール）で自動テストを実行し、その結果を目視で確認します。

事前に必要なもの：
- 開発担当者からリポジトリのローカル環境（Docker・Ruby・bundler）がセットアップ済みのPCを借りるか、開発担当者に画面共有で操作してもらってください。X（旧Twitter）のAPIキーなど、追加で受け取る必要のある認証情報はありません（今回のテストはローカルのダミーデータのみで完結します）。

手順：

1. ターミナルを開き、questboard プロジェクトのフォルダに移動します。
   ```
   cd questboard
   ```

2. データベースを起動します（すでに起動している場合はこの手順は不要です）。
   ```
   docker compose up -d postgres
   ```
   - 合格ライン: エラーが表示されず、コマンドが数秒で終了すること。

3. バックエンドのフォルダに移動します。
   ```
   cd src/backend
   ```

4. 今回追加されたデータベースの変更（`plan_id` を必須項目にする変更）を適用します。
   ```
   bundle exec rails db:migrate
   ```
   - 合格ライン: 最後の行が `== ... AddNotNullConstraintToUsersPlanId: migrated ...` のように `migrated` という文字で終わっていること。赤い文字の `Error` が出ていないこと。

5. 今回の変更を検証する自動テストをまとめて実行します。
   ```
   bundle exec rspec spec/requests/boards_spec.rb spec/requests/comments_spec.rb spec/requests/objects_spec.rb spec/requests/quests_spec.rb spec/services/permission_service_spec.rb spec/models/user_spec.rb
   ```
   - 合格ライン: 実行結果の最後の方に表示される `examples, 0 failures` の数字部分が **必ず `0 failures`** になっていること（例: `47 examples, 0 failures`）。もし `failures` の数字が1以上だったり、赤い文字の `Failures:` という見出しが出ていたりしたら、そのテキストをそのままスクリーンショットまたはコピーして開発担当者に共有してください。

これで「プラン（利用資格）が `member` でないユーザーはボード・オブジェクト・コメント・クエストの機能に一切アクセスできないこと」「ユーザーを新規作成すると自動的に `none` プラン（未加入扱い）が割り当てられ、プラン未設定によるすり抜けが起きないこと」が確認できます。
