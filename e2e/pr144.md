# PR #144: F9: フォロワーキャッシュ照合でプランを付与する

- PR: https://github.com/rictaworks/questboard/pull/144
- 対応issue: https://github.com/rictaworks/questboard/issues/132

## 非エンジニア向けユーザーテスト手順

このPRは画面の見た目や操作方法を変えるものではありません。「Xログインしたときに、有料プラン（member）が正しく付与されるかどうかの判定方法」をサーバー内部で変更しただけです。そのため、画面を操作する代わりに、下記のコマンドを実行して「これまでと同じ結果（テスト成功）が出ること」を確認します。

### 事前に必要なもの

- 開発担当者に、動作確認用のパソコンでこのリポジトリのセットアップ（`docker compose up -d postgres` の実行、`.env` ファイルの用意など）を済ませてもらってください。特別なAPIキーやパスワードの入力はこの確認手順の中では不要です。
- （参考）本番環境にこの変更を反映する際は、開発担当者が `X_FOLLOWER_GATE_TARGET_ACCOUNT_ID`（フォロワー判定の対象とするXアカウントのID）を本番サーバーの環境変数に設定する必要があります。これは非エンジニアが用意するものではなく、開発担当者側で対応します。

### 手順

1. ターミナル（黒い画面のアプリ、Macなら「ターミナル」、Windowsなら「WSL」または開発担当者が指定するアプリ）を開く
2. 次のコマンドをそのままコピーして貼り付け、Enterキーを押す

   ```
   cd /workspaces/questboard/src/backend && bundle exec rspec spec/services/auth/follower_gate_spec.rb spec/services/auth/x_session_creator_spec.rb spec/initializers/follower_gate_spec.rb --format documentation
   ```

3. 数秒〜数十秒待つと、画面の一番下に次のような行が表示されます。

   ```
   5 examples, 0 failures
   ```

   **この「0 failures」という表示が出ればOKです。** これは、「フォロワーとしてキャッシュに登録されているユーザーはmemberプランになる」「登録されていないユーザーはnoneプランになる」「一度memberになったユーザーは、判定に失敗してもmemberのまま維持される」「対象アカウントIDが設定されていないと起動時にきちんとエラーになる」という4つの動きが、すべて期待通りであることが確認できた、という意味です。

4. もし `failures` の数が1件以上（例: `2 failures`）赤い文字で表示された場合は、その画面をそのまま（スクロールして全部見えるように）スクリーンショットを撮り、開発担当者に送ってください。ご自身で原因を調べる必要はありません。
