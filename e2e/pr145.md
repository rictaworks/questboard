# PR #145: F9: フォロワーキャッシュの定期同期とアンフォロー検出を追加

- PR: https://github.com/rictaworks/questboard/pull/145
- 対応issue: https://github.com/rictaworks/questboard/issues/134

## 非エンジニア向けユーザーテスト手順

この変更には2つの確認対象があります。(1) 裏側で定期的に動くバッチ処理、(2) 管理者用の「例外ユーザー（手動ログイン許可）管理」画面です。

### 事前に必要なもの

- 開発担当者から次の情報を受け取ってください（本番の秘密情報のため、担当者以外に共有しないでください）。
  - `X_FOLLOWER_CACHE_SYNC_BEARER_TOKEN`（X API に接続するための認証トークン）※（1）の自動テストのみを行う場合や、ローカルで画面確認するだけの場合は不要です
  - 本番環境で画面を確認する場合のみ：管理画面のログイン情報 `ADMIN_BASIC_AUTH_USERNAME` / `ADMIN_BASIC_AUTH_PASSWORD`（ローカルで確認する場合は既定値 `admin` / `change-me` がそのまま使えます）
- パソコンに Docker と Ruby（バージョン 3.4.10）がインストールされていること（セットアップ方法が分からない場合は開発担当者に確認してください）

### 手順（1）：自動テストで確認する方法（X の認証情報は不要です）

1. ターミナル（黒い画面のアプリ）を開きます。
2. 次のコマンドを1行ずつ貼り付けて実行し、リポジトリのルートフォルダに移動します。
   ```
   cd questboard
   ```
3. データベースを起動します。
   ```
   docker compose up -d postgres
   ```
4. バックエンドのフォルダに移動します。
   ```
   cd src/backend
   ```
5. 必要な部品をインストールします（初回のみ、少し時間がかかります）。
   ```
   bundle install
   ```
6. 今回追加・更新された自動テストを実行します。
   ```
   bundle exec rspec spec/services/auth/follower_cache_sync_spec.rb spec/services/auth/x_followers_client_spec.rb spec/services/auth/follower_gate_spec.rb spec/initializers/follower_cache_sync_spec.rb spec/lib/tasks/follower_cache_spec.rb spec/models/follower_cache_spec.rb spec/controllers/admin/users_controller_spec.rb
   ```

**合格ライン**：実行結果の最後に `0 failures`（失敗が0件）と表示されればOKです。数字が入った `X examples, 0 failures` のような行が出ていれば成功です。赤字で `failures` に0以外の数字が出ていたら失敗なので、そのままの画面を開発担当者に共有してください。

### 手順（2）：管理画面「例外ユーザー（手動ログイン許可）管理」を実際に操作して確認する方法

上記の手順4・5まで終わっている状態から続けます。

1. 次のコマンドでデータベースを準備します。
   ```
   bin/rails db:prepare
   ```
2. 次のコマンドでサーバーを起動します（画面はこのまま起動し続けます。終わったら Ctrl+C で止めてください）。
   ```
   bin/rails server
   ```
3. ブラウザで次のURLを開きます。
   ```
   http://localhost:3000/admin
   ```
4. ユーザー名・パスワードを聞かれたら、ローカルで確認している場合は `admin` / `change-me` を入力します（本番で確認する場合は開発担当者から受け取った情報を入力します）。
5. 「KPI開発者ダッシュボード」画面が表示されます。右上の「例外ユーザー（手動ログイン許可）管理」ボタンをクリックします。
6. 「手動ログイン許可（例外ユーザー）管理」画面が表示されます。「新しい例外ログインユーザーの追加」フォームに、Xユーザーid欄に `99999999`、表示名欄に `テスト太郎` と入力し、「手動許可リストに追加」ボタンをクリックします。
7. 画面上部に緑色の「手動ログインを許可しました。」というメッセージが表示され、下の「登録済みユーザー一覧」の表に「テスト太郎」の行が追加され、「手動ログイン許可状態」の欄に「手動許可中」という緑のラベルが表示されればOKです。
8. その行の「許可を解除」ボタンをクリックします。画面上部に「手動ログイン許可状態を更新しました。」というメッセージが表示され、「手動ログイン許可状態」の表示が「通常判定 (X API基準)」に変わればOKです。

**合格ライン**：手順7・8の表示が上記の通りになればOKです。エラー画面（`500` や `We're sorry`）が出た場合や、メッセージ・表示が変わらない場合は失敗なので、その画面をそのまま開発担当者に共有してください。

### （任意・上級者向け）実際に X から取得して同期する手順

開発担当者から `X_FOLLOWER_CACHE_SYNC_BEARER_TOKEN` を受け取っている場合のみ実施してください。

1. `src/backend/.env` ファイルに、開発担当者から受け取った値を設定します。
   ```
   X_FOLLOWER_CACHE_SYNC_BEARER_TOKEN=（受け取ったトークンを貼り付け）
   ```
2. 上記の手順4まで完了した状態で、次のコマンドを実行します（通常は差分同期、必要に応じて `[true]` を付けると全件同期になります）。
   ```
   bundle exec rails auth:sync_follower_cache
   ```
   全件同期を試したい場合はこちらを実行します。
   ```
   bundle exec rails auth:sync_follower_cache[true]
   ```

**合格ライン**：コマンドがエラーメッセージ（赤字で `Error` や `Exception` と表示されるもの）なしに終了すればOKです。エラーが出た場合は、その画面をそのまま開発担当者に共有してください。
