# PR #170: PermissionServiceのtarget_stateキーを現在の呼び出し契約に限定

- PR: https://github.com/rictaworks/questboard/pull/170
- 対応issue: https://github.com/rictaworks/questboard/issues/40

## 非エンジニア向けユーザーテスト手順

この変更は画面の見た目を変えるものではなく、「ボードのロック解除メニューが正しい人にだけ表示されるか」「自分のコメントだけが編集できるか」という裏側の権限チェックロジックの整理です。以下の手順で、想定どおりに動くことを確認してください。

### 事前に必要なもの

- questboard にログインできるXアカウント（テスト用アカウントが2つあると理想的です。1つ目を「Aさん」、2つ目を「Bさん」とします）
- 開発担当者から、確認対象の環境のURL（プレビュー環境またはローカル環境）を受け取ってください

### 手順1: フレームのロック・ロック解除を確認する

1. Aさんのアカウントでログインし、任意のボードを開きます
2. ボード上の付箋やフレームを1つ選択し、右クリック（またはタップ長押し）してメニューを開きます
3. メニューから「ロック」を選び、フレームをロックします
4. 再度同じフレームを選択してメニューを開きます
   - **合格ライン**：ロックした本人（Aさん）には「ロック解除」の項目がメニューに表示されること
5. 一度ログアウトし、Bさんのアカウントでログインして同じボードを開き、Aさんがロックしたフレームを選択してメニューを開きます
   - **合格ライン**：ロックした本人ではないBさんには「ロック解除」の項目が表示されない、または操作できないこと

### 手順2: コメントの編集権限を確認する

1. Aさんのアカウントでログインし、ボード上の付箋やフレームに自分のコメントを1件投稿します
2. 投稿した自分のコメントを選択し、編集操作ができるか確認します
   - **合格ライン**：Aさんは自分が投稿したコメントを編集できること
3. Bさんのアカウントでログインし、Aさんが投稿したコメントを選択して編集操作ができるか確認します
   - **合格ライン**：Bさんは他人（Aさん）が投稿したコメントを編集できないこと

### 手順3（開発担当者向け・任意）: 自動テストの結果を確認する

画面確認が難しい場合は、開発担当者にお願いして以下のコマンドを実行してもらい、結果を確認する方法もあります。

```
cd src/backend && bundle exec rspec spec/services/permission_service_spec.rb
```

- **合格ライン**：すべてのテストが `failures` 0件で完了し、赤字（エラー）表示が出ないこと
