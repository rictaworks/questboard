# PR #142: 設計書を製品版仕様（Xログイン＋フォロワー判定）へ整合させる

- PR: https://github.com/rictaworks/questboard/pull/142
- 対応issue: https://github.com/rictaworks/questboard/issues/138

## 非エンジニア向けユーザーテスト手順

このPRは設計書（Markdown文書）のみの変更で、アプリの画面もAPIも変わりません。したがって確認していただくのは **GitHub上で設計書の図と表が正しく表示されるか** の目視チェックのみです。所要時間は5〜10分程度です。

事前に開発担当者から受け取るものは **ありません**（GitHubにログインできるアカウントだけあればOKです。パスワードやAPIキーの入力は不要です）。

### 手順1：設計書を開く

1. ブラウザで次のURLを開く。
   ```
   https://github.com/rictaworks/questboard/pull/142/files
   ```
2. 画面に `questboard_design_document.md` というファイル名が表示されていることを確認する。
3. ファイル名の右側にある **「⋯」（点が3つ並んだボタン）** をクリックし、メニューから **「View file」** を選ぶ。

**合格ライン**：文書のタイトル「questboard — ゲームUI/UXを応用したビジネスホワイトボード」が表示されていればOK。

### 手順2：図が12個すべて絵として表示されるか確認する

設計書には図が **12個** 含まれています。ページを上から下までゆっくりスクロールし、次の見出しの下にある図が **絵（線や四角で描かれた図）として表示されている** ことを確認してください。

| # | 見出し | 図の見た目 |
|---|---|---|
| 1 | 2. ER図 | 四角い箱が線でつながった図 |
| 2 | 3. DFD（データフロー図） | 丸や四角が矢印でつながった図 |
| 3 | 4.1 共同編集（モードレス操作→同期→演出） | 縦線の間を横矢印が行き来する図 |
| 4 | 4.2 競合（同一プロパティ同時編集） | 同上 |
| 5 | 4.3 Xログイン（フォロワーキャッシュ照合のみ） | 同上 |
| 6 | 4.4 フォロワー手動再判定（クールダウン付き） | 同上 |
| 7 | 5. クラス図 | 3段に区切られた箱が並ぶ図 |
| 8 | 6.1 入力インタラクション状態（F1） | 丸い状態が矢印でつながった図 |
| 9 | 6.2 クエスト状態（F5） | 同上 |
| 10 | 6.3 オブジェクト状態（F6） | 同上 |
| 11 | 6.4 プラン状態（F9） | 同上 |
| 12 | 7. ユースケース図 | 同上 |

**合格ライン**：12個すべてが絵として表示されていればOK。

**NGの例**：図があるべき場所に、絵ではなく
```
graph TD
  A --> B
```
のような英数字の文字列がそのまま並んでいる、または赤い枠で `Syntax error in graph` と表示されている場合はNGです。その見出し番号を開発担当者に伝えてください。

> 参考：開発側でも作図ツール（mermaid-cli v11.16.0）で12個すべて描画できることを確認済みです。もし表示されない場合は、ブラウザの再読み込み（Windowsは `Ctrl` + `F5`、Macは `Command` + `Shift` + `R`）を一度お試しください。

### 手順3：文章の内容が最新になっているか確認する

ブラウザのページ内検索（Windowsは `Ctrl` + `F`、Macは `Command` + `F`）を使い、次を確認します。

1. 検索ボックスに `Google` と入力する。
   **合格ライン**：1件も見つからない（「Googleログイン」の記述が残っていない）。
2. 検索ボックスの中身を消し、`basic / pro` と入力する。
   **合格ライン**：1件も見つからない（PR #142で置き換えられる前のプランマスタ表の記述「basic / pro」が残っていない。なお「BASIC認証」はこの検索語には一致しないため、無関係な記述としてノイズにならない）。
3. 検索ボックスの中身を消し、`basic/pro` と入力する。
   **合格ライン**：1件も見つからない（PR #142で置き換えられる前のER図の記述「code "basic/pro"」が残っていない）。
4. 検索ボックスの中身を消し、`member` と入力する。
   **合格ライン**：複数件見つかる（新しいプラン名に統一されている）。
5. 検索ボックスの中身を消し、`ログインを拒否する分岐は設けない` と入力する。
   **合格ライン**：1件見つかる（非フォロワーもログイン自体は成立する仕様に直っている）。
6. 検索ボックスの中身を消し、`クールダウン` と入力する。
   **合格ライン**：複数件見つかり、そのうち1つが見出し「4.4 フォロワー手動再判定（クールダウン付き）」である。

### 手順4：表が崩れていないか確認する

「1.6 テスト結果サマリ」「1.7 マスタデータ件数」までスクロールし、表が **格子状の表** として表示されていることを確認する。

**合格ライン**：
- 「1.6 テスト結果サマリ」の合計行が **638** と表示されている
- 「1.7 マスタデータ件数」のマスタ合計が **74件** と表示されている
- 縦棒（`|`）が文章中にそのまま並んで見えていない

以上4手順すべてが合格ラインを満たしていれば、このPRのユーザーテストは合格です。
