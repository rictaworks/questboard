# フロントエンド API

`src/app/api`（Next.js App Router の Route Handler）。UI のデータ取得はすべて Rails バックエンド（[`rails-backend.md`](rails-backend.md)）と sync-server（[`sync-server.md`](sync-server.md)）が担うため、ここに置くのは Next のプロセス自身についての情報を返す経路だけに限る。以下は現時点で実装済みのエンドポイントのみを記載する。

死活監視は Rails 側の `GET /healthz` を使う。フロントエンドには死活監視用の経路を置かない。

## インスタンス同定

| メソッド | パス | 説明 |
|---|---|---|
| GET | `/api/instance?instance=<識別子>` | 送った識別子が、稼働中のプロセスの起動時識別子と一致するかを答える |

### `GET /api/instance`

認証不要。応答本文は常に空。

| 条件 | ステータス |
|---|---|
| `QUESTBOARD_INSTANCE_ID` が設定されていて、クエリ `instance` がその値と一致する | 204 |
| 一致しない / クエリが無い / 環境変数が未設定 | 404 |

**識別子は返さない。** 問い合わせ側が知っている値と一致するかどうかだけを答える。反射すると、認証の要らない公開エンドポイントから匿名の呼び出し元が値を読み、ポーリングでインスタンスを列挙してデプロイ・再起動のタイミングを観測できてしまう。

`QUESTBOARD_INSTANCE_ID` は起動時に与える任意の文字列。**本番で設定する運用は前提にしていない**。未設定なら常に 404 を返すので、その場合この経路は存在しないのと同じ見え方になる。

用途は `test/not-found-http.test.mjs`。このテストは空きポートを予約してから `next start` を起動するが、予約したソケットを閉じてから子プロセスが bind するまでのあいだに別のプロセスが同じ番号を取る余地が残る。ページの文言では見分けられない（同じ成果物を配信する別インスタンスは同じ文言を返す）ため、起動ごとに生成した UUID を環境変数で渡し、この経路との照合が 204 を返してから検証を始める。

このハンドラは `export const dynamic = 'force-dynamic'` で静的化を止めている。静的化されるとビルド時の環境変数（通常は未設定）で判定し続け、どのインスタンスも同じ答えになって同定として機能しない。
